# cited_ticket_lint baseline — forward references already in history when the lint
# was introduced (T-2300, 2026-07-29).
#
# These are REAL defects, not false positives. They are listed here because a commit
# message cannot be edited: the only way to "fix" one is to rewrite published
# history, which is far more damaging than the wrong pointer. Without this file the
# weekly sweep would go red on these same four rows forever, and a weekly red nobody
# can action is exactly the alarm fatigue that gets a gate muted.
#
# Keyed on (short_sha, ticket_id) deliberately — a new or rewritten commit inherits
# no exemption, so this can only ever suppress the specific citations audited below.
#
# DO NOT add rows merely to silence a NEW finding. Prevention belongs at commit
# time: file first, then cite the id the allocator RETURNED. Once a bad citation is
# already published, however, its commit message is just as immutable as the rows
# that predated this lint. The post-publication procedure is therefore: independently
# confirm ancestry; audit whether the id captured unrelated work or the intended
# ticket merely landed later; repair every mutable shared surface if the referent is
# wrong; then baseline ONLY the exact (sha, id) pair with that rationale. The row
# records an unfixable historical defect — it does not declare the citation correct.
#
# Each row was confirmed by hand with `git merge-base --is-ancestor <birth> <sha>`
# — an independent mechanism from the rev-list ordering the lint itself uses — and
# its present-day referent was audited before the row was accepted.
#
