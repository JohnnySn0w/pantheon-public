# New repo: 'term:' URL-scheme handler for browser->terminal command shortcuts (POC)

## Ask

operator-filed via Telegram msg 10265 (2026-09-21T03:38Z): "New repo for a terminal shortcut via web browser url hack commands. Something like 'term:type a command'. Should have some installer bits per os so browsers pick it up."

Build a new repo (`term-shortcut` — GitHub, private, example-org) delivering a `term:` URL-scheme handler with per-OS installers. One click on a `term:<encoded-command>` link in a browser fires the named command in a terminal on the local machine.

## Context

**Scoping decisions (announced in TG msg 10266):**

1. **URL shape:** `term:<url-encoded-command>` (RFC 3986 percent-encoding). Alternatives (base64, JSON blob) rejected as over-designed for POC — url-encoding is what browsers already expect + copy-paste-safe. Fragment/query args reserved for later (e.g. `?cwd=/some/path`, `?shell=powershell`).

2. **Safety posture: confirm-before-exec, ALWAYS.** URL schemes are inherently untrusted input; a click on any web page could fire an arbitrary registered handler. Handler presents the decoded command in a modal/terminal prompt with an explicit accept/reject action. No allowlist mechanism at POC (would require config-file design + persona-of-trust discussion); confirm-every-time is the safe default. Could be relaxed later behind a flag once the operator model is set.

3. **Per-OS installers:**
   - **Windows** (primary per user_operator_primary_platform_windows): registry entries under `HKEY_CLASSES_ROOT\term` with `URL Protocol` empty-string marker + `shell\open\command` pointing to the handler binary. Delivered as a `.reg` file (importable) + optional `.msi`/inno-setup wrapper later.
   - **macOS**: URL scheme declared in a minimal handler `.app` bundle's `Info.plist` with `CFBundleURLSchemes`; registered via `LSHandlerRoleAll` when the app is launched once. Delivered as a `.dmg` or `.zip` with drag-to-Applications instructions.
   - **Linux**: `.desktop` file with `MimeType=x-scheme-handler/term`, registered via `xdg-mime default term-handler.desktop x-scheme-handler/term`. Delivered as an install-script that places the .desktop and runs xdg-mime.

4. **Handler shape:** small cross-platform binary (Go or Rust — Go probably wins for handler-binary-size + cross-compile simplicity). Reads the URL from argv, decodes, presents the confirm-and-execute prompt (native OS dialog on Windows/macOS; xterm-modal or notify-send on Linux), spawns the user's default shell to execute on accept. POC scope: no logging beyond stderr, no history, no per-user allowlist.

5. **Repo skeleton:**
   - `cmd/term-handler/main.go` — the handler binary entrypoint
   - `installers/windows/register-term-scheme.reg` — importable registry patch
   - `installers/macos/TermShortcut.app/` — handler-wrapping .app bundle template
   - `installers/linux/term-handler.desktop` + `install.sh` — .desktop + xdg-mime registration
   - `README.md` — usage: browser test-page + install-per-OS + security notes
   - `Makefile` — cross-compile targets (windows-amd64, darwin-arm64, linux-amd64)
   - LICENSE + `.gitignore` (Go-standard)

6. **POC milestones (in order):**
   - **M1** — Repo scaffold created, Go handler compiles + accepts `term:<encoded>` argv, decodes + prints the command. Confirms the URL-shape works.
   - **M2** — Windows registry-install + browser-click-fires-handler wired. Deliver: .reg file + Windows handler binary + browser test-page. This is the runnable milestone I committed to the operator.
   - **M3** — macOS + Linux installers added. Same shape.
   - **M4** — Confirm-before-exec dialog on each platform (Windows: `MessageBox` via `win-user32`; macOS: `osascript`-dialog; Linux: `zenity` or fallback).
   - **M5** — Optional polish: help text, `--dry-run` flag on the handler, install-verification script.

Not-in-scope for POC: allowlist configuration, remote execution (all commands run locally on the user's machine), history/logging, multi-user installs, service-mode.
