# Ticket DAG as a first-class lineage graph: auto-link new tickets + backfill orphans

## Ask

Realize the operator's aim (TG 2026-08-28): a first-class ticket lineage graph where all tickets connect properly and NEW tickets auto-join. Current state (specialist full scan 2026-08-28, 3322 tickets): 33% are ORPHANS with no lineage edge at all (no parent_ticket / depends_on / serves / implements / verifies / supersedes / informs). Edge coverage: parent_ticket 45%, serves 30%, depends_on 6%, implements 2%, verifies/supersedes/informs ~0% (barely used). New tickets are NOT auto-connected: T-3200+ still land 25% orphaned. TWO gaps to close: (1) AUTO-LINK AT FILE TIME — ticket.py makes every edge optional, so tickets land orphaned; add a file-time guard so a new ticket must carry >=1 lineage edge (parent OR serves OR depends), or auto-infer one (from-watch/auto-consumer tickets already get a parent_ticket — generalize that so no path files an orphan). (2) ORPHAN BACKFILL — a one-time connection pass over the ~1111 existing orphans (mostly done/ historical). OPTIONAL (3): a queryable/visual lineage-graph surface — grooming already walks the dep graph for cycles + stale-done-deps (T-0976), so the reader exists; extend it to a first-class graph view. Specialist can supply the orphan list + the scan script.
