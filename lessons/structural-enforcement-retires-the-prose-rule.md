## Observation

The companion lesson [`instruction-fidelity-collapse-discipline-vs-architecture.md`](instruction-fidelity-collapse-discipline-vs-architecture.md) names the failure mode: *discipline-by-prose without architectural backing degrades silently under cognitive load*. The remedy named there is structural enforcement. This lesson notes the **inverse arc** — once structural enforcement actually lands, the prose-tier rule becomes redundant and should drop per D10 (context-frugality / minimum-traversal-to-precise-info). The prose rule isn't dropped because it was wrong; it's dropped because architecture has absorbed its function. Continuing to enforce it as prose adds context-cost without enforcement-value.

The full arc has five phases:

1. **Prose-tier rule** — discipline pinned in CLAUDE.md, repeated in worker briefs, expected to be honored by reading.
2. **Research / incident surfaces the issue** — recurrence pattern OR external signal (vendor change, audit finding) triggers the move-to-architecture conversation.
3. **Structural enforcement lands** — pre-commit hook, branch protection, harness primitive, server-side check; whatever structurally prevents the bypass.
4. **Prose-tier rule becomes redundant** — workers can't actually violate the rule (or violations get caught structurally), so brief-language about it stops doing work.
5. **Prose rule retires; lessons-tier note preserves the WHY** — the rule drops from briefs + SOPs + CLAUDE.md per D10; a lessons-tier note captures *why the rule existed* + *what structural fix replaced it* so future agents reading old artifacts understand the lineage.

## Grounding

The founding case is **HERMES byte-sequence discipline** (per `~/CLAUDE.md` §`HERMES\.md` byte-sequence discipline; standing rule pinned by Orchestrator originally as project-tier policy after the operator surfaced).

- **Phase 1** (prose-tier rule, ~April 2026): the literal byte sequence `HERMES\.md` (uppercase, contiguous, no backslash at runtime) routes Claude Code requests to extra-usage billing via Anthropic's anti-abuse classifier. Worker briefs got the rule explicitly: "escape the period" / "use string concatenation in test fixtures" / "split or escape in commit messages."
- **Phase 2** (research / incident, 2026-04-29): research dispatch landed at `knowledge/episodic/2026-04-29-anthropic-flagging-diy-harnesses/notes.md`. Independent diagnosis: Boris Cherny's public X-thread re: anti-abuse classifier triggering on the byte-sequence; incident surface in the original Pantheon dispatch.
- **Phase 3** (structural enforcement, before 2026-05-10): pre-commit hook at `.githooks/pre-commit` runs `tools/hermes_diff_scan.py` on staged diffs; commit-msg hook at `.githooks/commit-msg` checks commit messages; `tools/watch_runner.py` runs the guard before any auto-commit (per the path-(c) eviction-remediation closed 2026-05-02). All commit paths are covered.
- **Phase 4** (prose-tier redundant, 2026-05-10 — the operator msg_1223): the question came in the form "Does HERMES discipline need to exist in instructions at this point, or is the commit hook sufficient?" Honest answer: hook is sufficient at commit-time; brief-language is cruft.
- **Phase 5** (this lesson): drops the HERMES line from the reviewer-pass step in `sop/standard/plan-first-dispatch.md` (the immediate mechanical drop); preserves the WHY in this lesson + retains the rule in `~/CLAUDE.md` as a worker-prose-tier guidance for AVOIDING hook-failures (the prose at the *worker generation* tier still has small load-bearing value: a worker who emits HERMES inadvertently in a plan-tier surface causes a confusing pre-commit failure later, so escape-in-prose still helps; but the *enforcement* function is structural).

The **counter-example** sharpening the principle: **plan-first discipline**. There is no harness primitive that says "must emit plan-tier surface before code." No pre-commit hook can detect "this is the wrong order." Plan-first stays load-bearing as prose because no structural enforcement exists. When (if) such enforcement exists — perhaps via a Claude Code harness primitive that would gate code emission on a plan-tier marker — the prose rule could retire too. Until then, the prose IS the enforcement.

The **in-flight case**: T-0156 (structural prevention of implementer-self-merge-to-main). Path 1 is GitHub branch protection; Path 3 is the `agent/<task>` branch convention. When both land cleanly across all repos, the brief-language hard-stop ("no self-merge") becomes redundant the same way HERMES brief-language did. The retirement should happen as part of T-0156's close paperwork, not as a separate cycle.

## Design implications

Three operational rules go-forward.

**1. After every structural-enforcement landing, audit the prose-tier rule for cruft.** The audit asks: "Is the prose still doing work, or is it now belt-and-suspenders to the structural fix?" If belt-and-suspenders, drop the prose per D10 + cite the structural fix in the cross-references of whatever doc held the prose rule. The natural touchpoint: structural-enforcement landing tickets (e.g., T-0156 on close) include a "prose-cruft audit" sub-deliverable in their acceptance.

**2. The lessons-tier note is the audit-chain artifact for the retirement.** A retired rule without a lesson-tier note breaks the audit chain — future agents reading old briefs see HERMES brief-language and don't know whether it's still load-bearing. The lessons-tier note is what lets the prose rule drop *cleanly*: it preserves the WHY + names the structural replacement + cites the artifact paths. This lesson IS that artifact for HERMES; future structural-enforcement retirements get their own lessons-tier notes (or this lesson grows a §Founding cases section as the pattern recurs).

**3. The principle has a precondition: structural enforcement must be actually reliable before prose retires.** If the pre-commit hook fails open when disabled, or the branch protection can be admin-bypassed, the prose still has a load-bearing fallback role. The retirement decision is a confidence call on the structural layer: "Is this enforcement reliable enough that the prose-tier fallback isn't needed?" For HERMES the answer is yes (hooks + watch_runner + history-audit triple-layer). For other cases the answer may be more partial (e.g., branch protection without admin-bypass-prevention is *mostly* reliable but not fully). Partial structural enforcement keeps partial prose; full structural enforcement retires full prose.

## Open questions

- **What's the rate at which structural-enforcement landings retire prose rules?** Today: HERMES is the founding case; T-0156 is in flight. Pace is "once or twice a quarter." If the pace accelerates (e.g., several harness primitives landing on Pantheon's prose-discipline surface), the prose-cruft-audit becomes a recurring practice rather than a per-cycle sub-deliverable.
- **Is there a register of currently-load-bearing prose rules + their structural-enforcement status?** Today: scattered (CLAUDE.md, persona briefs, SOPs, individual ledger entries). A single index (e.g., `notes/prose-rules-with-enforcement-status.md`) would make the cruft-audit faster — list each rule + its structural-enforcement state + the retirement-trigger condition. **Resolved 2026-06-23 (T-1280, ORG-012 sweep): won't-build.** At the pace the first open-question records (structural-enforcement retirements run once-or-twice a quarter — HERMES founding, T-0156 in flight), a standing global register is over-infrastructure: the cruft-audit is already correctly routed by Design-implication #1 to each structural-enforcement-landing ticket *on close* (scoped to the rule it retires, event-triggered, never stale), and a standing meta-register of prose rules would itself become a stale prose artifact — anti-thetical to this lesson's own D10/context-frugality thesis — with no demonstrated demand in the ~6 weeks since it was proposed. **Re-open trigger:** the first open-question's acceleration signal (several structural primitives landing on the prose-discipline surface in a single quarter), at which point a register would pay for itself; a one-time backlog cruft-sweep, if ever wanted, is a separate scoped task, not a standing index. Decided autonomously per msg-3733 (lesson-curation, below goal-level).
- **How much of the worker-generation-tier prose has the same retirement arc?** HERMES brief-language for *worker-output* is partly retained (avoid hook-failures; clean prose). Plan-first brief-language is fully retained (no structural enforcement). The general question: does *worker-prose-tier* discipline have a different retirement curve than *enforcement-tier* discipline? Probably yes; the lesson here applies most strongly to enforcement-tier rules.
- **What about the inverse-of-the-inverse?** When structural enforcement breaks (regression, config drift, vendor change) — does the retired prose rule come back, or does the audit-chain rely entirely on detecting + repairing the structural failure? Likely the latter (per P1 architecture-over-policy), but the failure mode hasn't been observed yet.
