# Pantheon ADRs

Architectural Decision Records for the org tier. Project ADRs live in their respective project repos; this directory is for decisions that span the hub or amend Pantheon's principles.

## Numbering

`ORG-NNN`. Default starting at `ORG-001`. Separate from any project's ADR ranges. Project ADRs live in their project's repo (per the operator msg_1199 + msg_1200 + msg_1205):
- `echo-prismatic/adr/` — 1–199 reserved for operator-authored vault, 200+ for agent-authored.
- `pantheon-pwa/adr/` — 1–49 reserved for operator-authored vault (if/when), 50+ for agent-authored (established 2026-05-13 via T-0302; first entry ADR-050).
- Future project repos: file a sibling ADR establishing their own range; check existing ranges to avoid collision.

Pantheon (this directory) uses `ORG-NNN` exclusively; no overlap with project numeric ranges.

## HITL field (mandatory)

Every ADR carries one of:
- **Authored** — human-written by the operator. Implicit on principle amendments he writes directly.
- **Ratified** — agent-proposed, operator-accepted. Status line carries `Ratified: YYYY-MM-DD by the operator` and the channel where ratification happened (Telegram, terminal, GitHub PR).
- **Autonomous** — agent-authored, unratified. Default state for orchestrator-initiated ADRs awaiting the operator's review.

## When to write one

- Choosing between reasonable approaches with rationale that matters
- Defining or changing an interface (between tiers, with workers, with project orchestrators)
- Amending or extending a principle in `rulebook/principles.md`
- Resolving (or explicitly preserving — see P6) a tension
- Any decision that crosses the autonomy bar (D3)

Do NOT write ADRs for: trivial refactors, styling, pure scaffolding, or things `BACKLOG.md` already tracks as work items.

## Format

Match the operator's vault-ADR style (see `echo-prismatic/adr/TEMPLATE.md` for the canonical shape, lifted from the operator's authored ADRs 001–011). Inline-header style, not a folder-per-ADR.

**Build-ticket label contract (T-1814, amended T-2806).** A ticket carved to build an ADR carries BOTH `build` and a namespace-correct join label in its frontmatter `labels:` list — `org-<NNN>` for `ORG-NNN` ADRs, `adr-<NNN>` for `ADR-NNN` ADRs, per the prefix→label-template map in `adr-namespaces.yaml` (repo root; a new prefix is a config add, not a code change). Both `org-NNN` and `adr-NNN` are accepted as join labels during the migration off the old adr-NNN-only convention. This is the join key `tools/ticket_grooming.py`'s ratified-unbuilt-ADR check uses to surface build gaps in the daily grooming digest.

**`build_disposition` (T-2806).** Every ADR frontmatter should carry `build_disposition: needs-build | no-build-needed | built`. `no-build-needed` and `built` both exempt an ADR from the ratified-unbuilt-ADR check — they mean "not an open build gap," whether because none was ever needed or because it's already shipped. `needs-build`, or the field being absent (pending backfill), makes the ADR eligible for the check.

**Zero-ticket backstop (T-2806).** The daily grooming check flags a ratified, needs-build ADR with **zero** matching build tickets in any state (inbox/active/done) — not only one with a stalled *open* ticket. A ratified ADR that silently never got a build ticket at all (the ORG-014 failure) is exactly the case this exists to catch. An ADR whose only matching ticket is already `done` is treated as already built and is not flagged.

**Prevent-at-creation (the operator, TG 7590; T-2806).** A landing ADR is rejected by `.github/workflows/adr-scoping-lint.yml` (`tools/adr_scoping_lint.py`) unless its frontmatter carries EITHER `build_disposition: no-build-needed`/`built`, OR a `scoping_ticket: T-NNNN`. Absence of `build_disposition` is treated as `needs-build` — a landing ADR must declare itself, not silently skip the question. The scoping ticket is expected to file the ADR's planning + follow-up build tickets on ratification. This is the structural primary; the zero-ticket backstop above is the safety net for anything that predates the rule or slips through (only genuinely NEW ADR files in a diff are checked — existing ADRs are grandfathered).
