# pantheon-pwa fresh worktree: vitest fails `Tsconfig not found` until `bun install` + `svelte-kit sync`

**Symptom.** A freshly-staged `git worktree add` of pantheon-pwa fails its web test suite immediately:

```
FAIL  tests/TicketActions.test.ts [ tests/TicketActions.test.ts ]
Error: Transform failed with 1 error:
[TSCONFIG_ERROR] Failed to load tsconfig for 'tests/setup.ts': Tsconfig not found
  Plugin: vite:oxc
```

`Test Files 1 failed (1) / Tests no tests` — the suite never runs. Same baseline test passes fine in the main checkout `/home/claude/pantheon-pwa`.

**Cause.** Two pieces the worktree lacks because they are gitignored / generated, not tracked:
1. `web/node_modules` — not copied into a new worktree.
2. `web/.svelte-kit/` — generated by `svelte-kit sync`. The web `tsconfig.json` extends `./.svelte-kit/tsconfig.json`; without it, vite/oxc can't resolve the tsconfig for `tests/setup.ts`.

**Do NOT symlink `web/node_modules` from the main checkout** — vite's oxc transform resolves module paths through the symlink (`../../../home/claude/...`) and fails differently. Use a real install.

**Fix (run in the worktree's `web/` before any vitest/build):**
```
cd <worktree>/web
bun install          # bun global cache makes this ~sub-second
bunx svelte-kit sync # regenerates .svelte-kit/ → provides the tsconfig
```
Then `bunx vitest run` works (e.g. TicketActions → 11 baseline tests green).

**When briefing an implementer on a pantheon-pwa worktree dispatch**, pre-run both in the staged worktree (or name them in the brief), the same way echo worktrees need `stage-echo-worktree.sh` for the vendor symlink. Surfaced T-0854 (2026-06-06).
