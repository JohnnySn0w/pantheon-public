# bugs/

Reusable catalog of technical gotchas — symptoms with surgical fixes that recur across cycles. Distinct from `incidents/` (one-shot postmortems for specific events) and from `adr/` (architectural decisions). One file per gotcha; filename is the keywords for grep/agent-search lookup.

## When to add an entry

A bug belongs here when:

- The symptom is reproducible (not a one-off race condition specific to one run) — **and the entry carries the evidence of it** in the `## Verification` field (a one-line repro command, or the specific observation that confirmed it). This is P1 applied to our own memory: an admission criterion that lives only in this README is a *policy*, and policies decay — measured 2026-08-03 (T-2525), only 4 of 110 entries carried repro evidence. Carried *with* the entry, that evidence is what keeps the fix re-checkable later and safe to grep-and-apply in a neighbouring domain — and grep-and-apply across domains is exactly what `bugs/` is for (cf. `adr/ORG-058`; T-2475 / arXiv:2604.17658, on verified episodic memory enabling cross-domain transfer).
- The fix is surgical (not a discussion, not a research thread, not a behavioral pattern — those go elsewhere).
- It's likely to recur (any future cycle in the same domain — vitest, bun, systemd, etc — could hit it).

When in doubt: prefer adding. The cost is low (one file); the benefit is anyone hitting the symptom in the future grep-finds the fix instead of re-discovering it.

## When NOT to add

- One-shot incidents → `incidents/` (postmortem format).
- Behavioral rules / "how HO should act" → auto-memory at `~/.claude/projects/-home-claude/memory/feedback_*.md`.
- Architectural decisions → `adr/`.
- In-progress investigations → `knowledge/episodic/<date>-<topic>/`.

## When to retire an entry

Adding is only half the lifecycle. A gotcha that has been **fixed upstream** — a dependency bumped past the bug, the harness changing the behavior, the code path removed — leaves an entry that still grep-matches and still *reads as current*. That is **worse than no entry**: an agent applies a fix for a problem that no longer exists, or trusts a "safe because X" whose X has changed. This is the supersede/decay half of the entry lifecycle (`adr/ORG-058`), applied to `bugs/`.

- **Trigger (opportunistic).** Whenever you touch an entry — cite it, apply its fix, re-measure — re-run its `## Verification`. If the symptom no longer reproduces, retire it **in the same pass** (this is why the Verification field must be re-runnable, not a "I tested it" assertion).
- **Retire, don't silently leave.** Mark it at the top: `**RETIRED <date> — <reason>** (e.g. fixed upstream in dep X 3.x / harness commit Y / code path removed in Z).`
- **Banner vs delete.** Keep a **RETIRED banner** when the entry documents a real past hazard someone could still re-encounter on an older version (the banner turns it into a "this WAS true; here's what changed" note). **Delete** when the entry is purely obsolete and would only add grep noise. When in doubt, banner — a retired-but-labelled entry never misleads, a deleted one can't be re-found.
- Note: a missing `## Verification` on a legacy entry does NOT mean it is wrong or retirable — most were reproduced by whoever wrote them; what is missing is the evidence travelling with the memory. Do not retire on a missing-evidence basis; retire only when re-checking shows the symptom is gone.

## File structure

```markdown
---
symptom: "one-liner of what you're seeing"
fix: "one-liner of what to do"
domain: "vitest" / "bun" / "systemd" / etc
---
## Symptom
[copy-pastable error or behavior]

## Cause
[1-2 sentences, why it happens]

## Fix
[code snippet or steps]

## Verification
[REQUIRED for new entries — the evidence that the "reproducible" admission criterion was actually met, travelling WITH the entry: a one-line command that reproduces the symptom, or the specific observation that confirmed it (a measured value, an exit code, a log line). Not "I tested it" — the actual re-runnable check or the witnessed fact, so a future reader can re-confirm the entry still holds before trusting it. Template-forward: required going forward; existing entries are not retrofitted.]

## Discovered
- ticket-link, commit-link, date

## Keywords
comma-separated terms a grepping agent might use
```

The `## Keywords` block at the bottom is load-bearing — it's the search surface. Include obvious terms (the error string, the tool names, the symptom verbs), not just the canonical name.
